# Scenario release-parity evidence

The checks below ran on 13 November 2026 on macOS arm64. They exercise synthetic
scenario artifacts through installed consumers and the native Rust runtime.

## Results

- Five artifact envelopes were generated by the scenario schema classes from
  the `v0.6.0` tag at commit
  `3459f4528c11ceba8d1e5840d3da852dfb8d58bd`. The current Python consumer
  preserved every field and the maximum unsigned 64-bit seed. Julia preserved
  the seed as an integer and R preserved its exact JSON token. All five imports
  reported replay unavailable because their envelopes contain no simulation
  payload. An invalid timestamp was rejected in the Python check.
- An optimized native build at
  `3681c8a820e7f3f852ff7429687ba3997cbcae3f` generated 24 artifacts.
  These cover a Logistic case, five seeds across two homogeneous Kairos engines
  with two imitation rates, and connected, edgeless, and directed weighted
  network cases. The current optimized Python, Julia and R consumers imported
  all 24 and reproduced the retained numeric paths and recorded request and
  completion events. Julia and Python used exact equality. R used
  `all.equal` with tolerance `1e-12`.
- The current Python consumer tested 16 fixed-pool substitution designs across
  initial adoption fractions 0, 0.1, 0.5 and 1 and hazards 0, 0.1, 0.5 and 1.
  Incumbent counts matched `pool * exp(-hazard * time)` and the sum of
  incumbent and entrant counts conserved the pool at times 0, 1, 2 and 5.
  All 16 current artifacts replayed to identical results.

The two native source revisions both declare `0.7.0-alpha.1`. Their replayed
sample values and events matched, while their result metadata differed. For
example, the Kairos revision and checkpoint scope changed and the current result
added a dispatch count. Matching the version string therefore leaves source
identity and full-result parity to be established independently. Cross-version
native replay, broader stochastic and substitution designs, other platforms,
and complete release acceptance remain open.

## Repeat the checks

Run from the repository root with a repo-local Python 3.15.2 environment
containing the installed Innovate wheel and Polars 2.1.0. Set
`SCENARIO_PYTHON` to that interpreter and `SCENARIO_EVIDENCE` to this
directory.

```sh
"$SCENARIO_PYTHON" "$SCENARIO_EVIDENCE/verify.py"
"$SCENARIO_PYTHON" "$SCENARIO_EVIDENCE/prepare_bindings.py" "$SCENARIO_BINDING_INPUTS"
julia --project=bindings/julia "$SCENARIO_EVIDENCE/verify_bindings.jl"
Rscript "$SCENARIO_EVIDENCE/verify_bindings.R"
```

The Julia and R checks use `SCENARIO_BINDING_INPUTS` and
`INNOVATE_NATIVE_LIBRARY`. Install the R binding in an isolated R library and
set `R_LIBS_USER` to that library. Julia must resolve the project dependencies.

To regenerate the historical native response, extract the named historical
commit's `Cargo.toml`, `Cargo.lock` and `rust` tree to an isolated directory.
Copy `historical_producer.rs` into
`rust/crates/innovate-core/tests/scenario_historical_receipt.rs`, set
`SCENARIO_RECEIPT_PATH` to an output path and run
`cargo test --release --locked -p innovate-core --test scenario_historical_receipt`.
The producer's timestamp fields reflect the time of its new run.

To regenerate the legacy envelopes, extract `src/innovate/scenario/schemas.py`
and `src/innovate/utils/validation.py` from the named tag, place the extracted
`src` on `PYTHONPATH` in the isolated historical environment, and run
`legacy_producer.py` with an output filename. The historical producer uses its
original NumPy-backed validator.
