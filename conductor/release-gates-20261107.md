# Native innovation release gates

Current status: planned migration and evaluation. The next supported architecture is Rust-only scientific execution with Polars/Arrow and no pandas/xarray support. A policy document does not make the present hybrid source compliant.

## Independent acceptance units

Native scientific core, data/language bindings and optional integrations have distinct acceptance records. Each advertised capability retains every applicable scientific/native/security/consumer requirement. Unclaimed experimental work stays visible and pending; it does not block an unrelated scoped release. No requirement is deleted by this separation.

Static competition cases do not require Kairos dynamics. General hype validation does not require a medicines dataset. Native performance acceptance does not require optional simulation benchmarks. A core Innovate release does not require Voiage or Paignia integration. Claiming any of those integrations does require its exact provider, native execution and installed-consumer receipts. The authoritative packet details are in [the taskbook](innovation-taskbook-20261107.md), especially G04/H06/V04/V05/Q05.

## Alpha completion

- Scope and ownership are accurate; retired host implementations are unavailable in supported production entrypoints.
- Each retained model has explicit dynamics, observation type, parameter constraints, execution status and unsupported cases. Convergence, identification, predictive evidence and causal assumptions are separately reported.
- Deterministic native models and interfaces pass independent references and Python-absent execution. Pandas/xarray objects are rejected with migration guidance.
- Invalid inference cannot yield posterior-labelled samples. Descriptive contrasts cannot silently become adjusted causal estimates. Prior-only inference that ignores data is rejected by the applicable calibration controls.

## Beta

- Every advertised beta model-operation-payload combination has native dispatch, numerical, uncertainty and installed-consumer receipts.
- Clean minimal and supported-extra installs contain neither pandas nor xarray. External test-oracle environments are separate and cannot be reached by production dispatch.
- Native Polars/Arrow lifetime, null/category/unit/schema and cross-version tests pass. Lazy/eager/materialised paths preserve declared semantics within resource budgets. Stable domain/FFI contracts do not expose changing third-party layouts.
- Actual standalone feature closures prove optionality, including normal/build dependencies and root patches. Any advertised Kairos/game/Voiage integration uses accepted exact artefacts and has its own execution/consumer evidence; it is not a prerequisite for an unrelated core capability.
- Empirical examples and datasets qualify the declared scientific scope. Cross-domain forecasting claims require their registered non-medical comparisons. Medicines claims additionally require the qualified medicines panel and M03-M05 source-vintage/measurement tests; that cohort is not mandatory for the general core or hype baseline. No broad external-validity claim is inferred from a small fixture.
- Windows x64, Linux x64 and macOS arm64 packages are tested where advertised. Other architectures/backends remain unsupported until measured; no fake GPU/HPC matrix.

## Release candidate

- ABI/API/schema migration tests, FFI ownership and malformed-input fuzz/property tests pass. Resource limits, deterministic seed semantics, cancellation and recovery are documented.
- Rust fmt/clippy/test, Python-interface tests, meaningful mutation tests and at least 90% new-code line coverage pass without weakening stricter controls. Critical failure paths have branch tests.
- Adversarial scientific controls include likelihood/data-dependent calibration, applicable transformation invariants and invalid/stale fit handling. Hype claims include scale/measurement identification; medicines claims include supply/recording shocks and effective versus known-at dates; game claims include lawful observations and solution guarantees.
- Joint outcomes distinguish parameter/model/measurement/equilibrium/simulation/numerical uncertainty. Advertised decision integration passes conditional-average/noise and signed-information estimand tests; absent decision integration cannot imply those capabilities are supported.
- Security/dependency/licence audit, SBOM, reproducible build checks where feasible, hashes and provenance are retained. Candidate qualification and reproducible release locks are separate. Git-only closures have an explicit lawful distribution route; a local build does not establish publishability.
- Independent clean-environment reproduction is recorded accurately. Automated reviewers are labelled automated; the single-maintainer policy does not invent a second human approval requirement.
- Documentation examples execute installed artefacts, not source-injected paths. Benchmarks include equivalent work/precision, failure, memory, cold/warm and end-to-end cost, retaining negative results. Native and optional-integration receipts are separate.

## Stable scoped release

- All mandatory RC gates for the claimed scope pass on the exact release commit and distributable artefacts. A failed/skipped/unrun/stale mandatory gate blocks that promotion; a historical green run cannot qualify changed source.
- The support matrix enumerates stable, experimental and unavailable operations, generated from executable evidence where possible. Every previously promised capability retains an explicit completion/retirement decision and migration record.
- Negative controls verify both directions: missing optional providers do not block a core-only release, while an advertised integration without its required evidence does block its release. Do not convert a required method into an optional label merely to evade a failed test.
- Required release authorisation is obtained. Publication and journal submission remain separate actions, not automatic consequences of a plan checkbox.
- Reproducible scientific examples and real research use support the initial scoped software paper. A medicines manuscript needs the medicines receipts; the general software paper need not wait for that optional study. Performance leadership, broad empirical validity and post-frontier novelty require separate comparative studies.

Q01-Q05 own the executable checks; this checklist is not a second status ledger. Existing native/HPC alignment gates are neither waived nor incorrectly treated as proof of the new release. No implementation or release is accepted by this planning update.
