# DataFrame engine experiments

pandas plus PyArrow remains the default Python tabular surface for Innovate.
The public compatibility boundary is still the functional kernel schema and
Arrow-compatible payloads. DataFrame engine experiments sit behind that
boundary and must not change model inputs, kernel responses, or binding
contracts.

## Experiment scope

The current inventory is:

`pandas`
   Python-facing tabular ergonomics for preprocessing, plotting, model
   comparison, and kernel table helpers.

`PyArrow`
   Durable interchange for kernel arrays, kernel tables, diagnostics artifacts,
   discovery metadata, and language-binding payloads.

`Polars`
   Optional downstream Arrow consumer for selected experiments. Polars is
   installed only through `innovate[dataframe]`. Polars is experimental until
   benchmark evidence and compatibility gates justify broader support.

## Candidate workloads

The first candidate workloads are benchmark corpus metadata, diagnostics
artifact tables, kernel table round-trips, and model-card refresh tables. These
are table-heavy paths where lazy execution or Arrow-native conversion may
improve throughput or memory use without changing model semantics.

Kernel schemas and Arrow-compatible payloads remain the public contract.
Polars lazy query plans are not a public contract, and neither are
engine-specific expression trees. Results must round-trip back to kernel table
payloads before they are treated as stable outputs.

## Fallback behavior

The default engine is `pandas+pyarrow`. Requesting `polars` uses the
experimental Polars path only when the dependency is installed. If fallback is
allowed and Polars is unavailable, the helper returns a pandas plus PyArrow
DataFrame and records fallback metadata in `DataFrame.attrs`.

Strict callers can disable fallback to fail fast when an optional engine is not
available. This keeps optional DataFrame engines out of the required dependency
set while still making experiments reproducible.

## Benchmark attribution

Benchmark evidence must report row count, column count, correctness hash,
runtime, and memory fields. Results must also state whether a win came from
tabular execution, XLA-backed numerical kernels, or both. XLA-backed numerical
kernels are evaluated separately because DataFrame engine choices should not
hide array-kernel acceleration decisions.

## Promotion criteria

An optional DataFrame path can move beyond experimental only when it has:

- correctness parity with pandas plus PyArrow;
- reproducible benchmark evidence;
- no public API drift;
- an explicit optional dependency gate;
- fallback behavior that preserves the stable pandas plus PyArrow surface.

API reference for `innovate.dataframe_engines` is generated by `starlight-polyglot`.
