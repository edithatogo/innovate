These tutorials use the current Rust and Polars development API. Install the
[locked development environment](/innovate/user-guide/installation/) first.
Each current tutorial displays its registered example file, expected output,
interpretation and limits. Run the unchanged file successfully before adapting
it to a new analysis.

## Complete and explain a workflow

<Steps>

1. **Run the original example.** Use the installed checkout and command shown
   by the tutorial. Compare its output with the displayed contract and stop to
   investigate a failed assertion.
2. **Explain the result.** State the quantity, units, inputs, model assumptions,
   relevant diagnostics, failure behavior and the inference the example does
   not support. Try the tutorial's reader task before revealing its answer.
3. **Change one assumption or input.** Predict what should change, then run
   the revised analysis. New data or assumptions need their own checks; a
   passing original example does not qualify the revision.

</Steps>

## What passing a tutorial establishes

Passing a synthetic example establishes its stated software checks. It does not
establish empirical accuracy, causal identification, interval coverage or
suitability for a particular population. The
[documentation quality guide](/innovate/maintainers/documentation-quality/)
separates structure, execution and broader scientific and reader-task review.
Use the [native capability guide](/innovate/native-migration/) to inspect exact
model, variant, operation and quantity conventions and remaining qualification
limits.
